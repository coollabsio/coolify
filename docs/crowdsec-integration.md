# Protect Coolify with CrowdSec (Traefik access logs)

Feed the Coolify proxy's Traefik access logs into CrowdSec and block malicious
IPs at the proxy — for the Coolify dashboard and every hosted resource.

Two pieces are involved:

1. **Track B (code, regen-safe)** — a Proxy setting that makes Traefik write
   JSON access logs in production and keeps writing them across proxy
   regenerations.
2. **Track A (operational)** — deploy CrowdSec + a bouncer and attach the
   bouncer as a global Traefik middleware.

## 1. Enable JSON access logs (Track B)

Server → Proxy → **Enable access logs (JSON)** → restart the proxy.

This writes `/data/coolify/proxy/access.log` (JSON, one object per request).
The setting is stored in `proxy.access_log_enabled` and re-emitted by
`generateDefaultProxyConfiguration()` on every regenerate, so it survives a
proxy **Reset** (unlike manually added `--accesslog` flags, which the
regenerator strips by design — see `extractCustomProxyCommands()`).

Verify on the host:

```bash
tail -f /data/coolify/proxy/access.log   # JSON objects, not CLF
```

## 2. Deploy the CrowdSec stack (Track A)

Create a one-click service from the **CrowdSec** template
(`templates/compose/crowdsec.yaml`). It runs:

- `crowdsec` — engine + Local API, parsing the bind-mounted access log via the
  templated `acquis.yaml` (`type: traefik`), with the `crowdsecurity/traefik`
  collection.
- `bouncer-traefik` — a forwardAuth bouncer, attached to the external
  `coolify` network so the proxy can reach it.

The bouncer key is auto-generated by Coolify (`SERVICE_PASSWORD_CROWDSECBOUNCER`)
and shared by both containers (`BOUNCER_KEY_traefik` registers it in CrowdSec).

> The external `coolify` network must already exist (it does on any server
> running the Coolify proxy). The template assumes the proxy log lives at
> `/data/coolify/proxy/access.log` (step 1).

## 3. Attach the bouncer as a global middleware

Add a dynamic config file (Server → Proxy → Dynamic Configurations) named
**`crowdsec.yaml`** (any name except the reserved `coolify.yaml`):

```yaml
http:
  middlewares:
    crowdsec:
      forwardAuth:
        address: http://bouncer-traefik:8080/api/v1/forwardAuth
        trustForwardHeader: true
```

Apply it to **all** routers via entrypoint default middlewares. In
Server → Proxy → Configuration add to the `coolify-proxy` `command:`:

```
--entrypoints.http.http.middlewares=crowdsec@file
--entrypoints.https.http.middlewares=crowdsec@file
```

These are preserved across regenerations (not in the strip list). Save and
restart the proxy.

To protect **only the Coolify dashboard** instead of everything, skip the
entrypoint flags and add `crowdsec` to the dashboard router's middleware list
in the dynamic file rather than globally.

### Alternative: Traefik plugin bouncer

Instead of the forwardAuth container you can use the in-proxy plugin
(`maxlerebourg/crowdsec-bouncer-traefik-plugin`). Add to the proxy `command:`:

```
--experimental.plugins.crowdsec.modulename=github.com/maxlerebourg/crowdsec-bouncer-traefik-plugin
--experimental.plugins.crowdsec.version=v1.4.4
```

and define the middleware as `plugin.crowdsec` in `crowdsec.yaml` instead of
`forwardAuth`. The plugin needs Traefik to reach GitHub on startup; the
forwardAuth container does not. Both apply globally via the same entrypoint
flags.

## 4. Verify end to end

```bash
# CrowdSec is ingesting Traefik logs
docker exec crowdsec cscli metrics
docker exec crowdsec cscli collections list   # crowdsecurity/traefik enabled

# Trigger detection (404 flood from a test box)
for i in $(seq 1 40); do curl -s -o /dev/null https://<coolify-fqdn>/x$i; done
docker exec crowdsec cscli alerts list

# Enforce: ban a test IP, expect HTTP 403 from Traefik, then unban
docker exec crowdsec cscli decisions add --ip <test-ip> --duration 5m
docker exec crowdsec cscli decisions delete --ip <test-ip>
```

Confirm the Coolify dashboard, ACME certificate issuance, and a sample app all
still work with the bouncer active. Never ban your own admin IP; recover with
`cscli decisions delete --ip <ip>`.

## 5. Monitoring

- `cscli metrics`, `cscli decisions list`, `cscli alerts list`.
- CrowdSec exposes Prometheus metrics on `:6060`.
- Optional hosted dashboard: `docker exec crowdsec cscli console enroll <key>`.

## Caveats

- The entrypoint middleware also fronts the dashboard and the ACME HTTP-01
  path. If the proxy sits behind Cloudflare/another LB, set Traefik
  `forwardedHeaders.trustedIPs` (and the bouncer's trusted IPs) so decisions
  act on the real client IP, not the upstream proxy IP.
- Without Track B, access-log flags added by hand are dropped on a proxy
  Reset. The toggle is the durable fix.
